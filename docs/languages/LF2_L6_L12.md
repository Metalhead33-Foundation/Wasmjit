## 1. How to read this note

Three different things share the word "not run", and conflating them would be
dishonest:

| Status | Meaning | What would change it |
|---|---|---|
| **not run — no charter** | The cluster was never shortlisted; nothing was built because nothing was commissioned | a charter plus `T3` |
| **not run — no toolchain** | The toolchain could not be obtained in this environment (licence, no release, or an install too large for the study box) | the install, then a `C3` arm |
| **not run — blocked** | The arm would fail for a reason already established (`F3`, the JS-host contract, the `Single` contract) | the named finding closing |

None of them is a verdict. A row in this note is exactly as undecided as it was
in `LF-1`, unless it says otherwise.

## 2. `L8` — the one arm run here

### 2.1 `T09` — Go on `wasip1` (Yellow)

Go is not an LLVM toolchain, which is why `LF-1` kept it out of `L2`. Two shapes
were built with Go 1.27.3:

```
GOOS=wasip1 GOARCH=wasm go build -o t09_go.wasm .                    # command module, _start
GOOS=wasip1 GOARCH=wasm go build -buildmode=c-shared -o t09_go_lib.wasm .  # reactor, _initialize
```

The **command** shape runs, and its `main` executes:

```
call _start/void()hello from Go on wasip1
wasi_exit=0
```

The **reactor** shape is the one an embedder needs, and it is the one the bar is
built on:

```
call _initialize/void() -> void
call add/i32(19,23) -> i32=42
memory memory: 2949120 bytes (45 pages) max=4294967296 shared=0
```

Three facts follow from the measurements:

1. **`//go:wasmexport` needs `_initialize` first.** Calling the export without it
   aborts inside the Go runtime:
   `runtime: wasmexport function called before runtime initialization`.
   The reactor build makes that explicit, which is why it is the only shape worth
   documenting for an embedder.
2. **The WASI surface is 16 functions**, including `poll_oneoff`,
   `fd_fdstat_set_flags` and `fd_prestat_*`. Our shim implements all of them; a
   real embedder's shim would be larger because `path_open` is where a Go program
   would touch the filesystem.
3. **Start-up grows the memory to 45 pages (2.9 MB) before the first export**
   and does not shrink it. That is the number `LF-1` could only guess at, and it
   is what the allocation budget
   ([`SAFETY.md`](../SAFETY.md) §2.3) sees at instantiate time.

**Verdict: Yellow.** It passes the bar with a build flag (`-buildmode=c-shared`)
and a real WASI shim; neither is an engine change. Two bar items were not
exercised on this arm — a native host import (item 2) and a second module's
export (item 3) — because the mechanism is the engine's and is proven on `T02`
(cross-module) and `T06`/`T26` (host import). `T08` (`GOOS=js`) remains killed:
`wasm_exec.js` is the runtime, and nothing here changes that.
